# কাঠামো ও রক্ষণাবেক্ষণ

দুই মাসের কাজ, হাজারখানেক ছবি, অনেকগুলো পেজ। এই ফাইলটা সেই সিদ্ধান্তগুলোর জন্য
যেগুলো **শুরুতে নেওয়া সহজ, পরে বদলানো ব্যয়বহুল**।

---

## এখনকার অবস্থা — অনুমান নয়, মাপা

| | |
|---|---|
| `client/public/` মোট | **১২৯ MB** |
| শুধু হোমপেজের অ্যাসেট | **১০৭ MB** (ছবি ৭৩, ভিডিও ৩৪) |
| সবচেয়ে ভারী একটা ফাইল | ৯.৬ MB (`legacy-slide-2-livingroom.png`) |
| ৮ MB-র বেশি ফাইল | ৮টা |

আর ওই ৯.৬ MB ছবিটাকে ১৯২০px চওড়ায় নামিয়ে রূপান্তর করলে:

| ফরম্যাট | আকার | সাশ্রয় |
|---|---|---|
| JPEG | ৩৫৩ KB | −৯৬.৪% |
| WebP | ৩২৪ KB | −৯৬.৭% |
| **AVIF** | **২৪৪ KB** | **−৯৭.৫%** |

**একটা ছবিতেই ৯.৪ MB বাঁচে।** দেখতে পার্থক্য নেই — মূল ফাইলটা ২৮১৬px চওড়া PNG,
যেটা কোনো পর্দাতেই পুরোটা দেখানো হয় না।

---

## ১. ছবি — এটাই সবচেয়ে বড় ঝুঁকি

**হিসাবটা করে দেখুন।** এখন গড়ে প্রতি ছবি ~৫ MB। ১০০০ ছবি হলে **৫ GB**।

- GitHub একক ফাইল ১০০ MB-র বেশি নেয় না, আর রিপো ১ GB পেরোলে `clone` মিনিটের
  পর মিনিট নেয়
- প্রতিটা ডিপ্লয়ে পুরো `public/` সার্ভারে যায় — বিল্ড ধীর, ডকার ইমেজ বিশাল
- একবার git ইতিহাসে ঢুকলে **মুছে ফেললেও আকার কমে না**

### নিয়ম

**`public/` এ শুধু ব্র্যান্ডের স্থির জিনিস** — লোগো, favicon, OG ছবি। ২০-৩০টার
বেশি নয়, মোট কয়েক MB।

**বাকি সব ছবি ব্যাকএন্ড দিয়ে।** এটা নতুন করে বানাতে হবে না, **ইতিমধ্যেই আছে**:

- `backend/src/app/modules/upload/` — আপলোড এন্ডপয়েন্ট
- `client/next.config.ts` এ Cloudinary আর ব্যাকএন্ডের `/uploads` দুটোই
  `remotePatterns` এ অনুমোদিত
- অ্যাডমিন ড্যাশবোর্ডে আপলোডের পাতা আছে

মানে পাইপলাইনটা তৈরি — শুধু ব্যবহার করতে হবে।

**মূল ফাইল কখনো রিপোতে নয়।** ডিজাইনার বা AI থেকে আসা ৮-১০ MB-র মাস্টারগুলো
`recource/originals/` এ থাকবে (ওটা `.gitignore` করা)। রিপোতে যাবে শুধু
রূপান্তরিত সংস্করণ।

**একটাই স্ক্রিপ্ট রূপান্তর করবে**, হাতে নয় — তাহলে প্রতিটা ছবি একই মানে, একই
মাপে, একই ফরম্যাটে যাবে।

## ২. কন্টেন্ট — পেজ প্রতি একটা ফাইল

এখন প্রতিটা কম্পোনেন্টের ভেতরে তার নিজের লেখা আর ছবির পথ হার্ডকোড করা —
`DivisionPanels.jsx` এ চারটা প্লেটের নাম, `Reels.jsx` এ ছয়টা ভিডিওর তালিকা।
ক্লায়েন্ট একটা শব্দ বদলাতে বললে কম্পোনেন্ট খুলতে হয়।

**প্রস্তাব:**

```
src/content/home.ts     ← হোমপেজের সব লেখা, ছবির পথ, লিংক
src/content/foam.ts
src/content/mattress.ts
```

কম্পোনেন্টে থাকবে শুধু গঠন আর আচরণ। লেখা বদলাতে একটাই ফাইল খুলতে হবে, আর
git-এ দেখা যাবে ঠিক কোন শব্দ কবে বদলেছে।

> **একটা টানাপোড়েন আছে, জেনে রাখুন।** ব্যাকএন্ডে `siteContent` মডিউলটা পূর্ণাঙ্গ
> (model, service, controller, routes) আর অ্যাডমিনে তার পাতাও আছে — অর্থাৎ
> **আপনার নিজের CMS তৈরি**। TS ফাইলে লেখা রাখলে ক্লায়েন্ট নিজে বদলাতে পারবেন
> না, আপনাকে বলতে হবে।
>
> আমার পরামর্শ: **এখন ফাইলেই থাক**। দুই মাস ধরে লেখা বারবার বদলাবে, ফাইলে
> বদলানো দ্রুত আর git-এ ইতিহাস থাকে। সাইট দাঁড়িয়ে গেলে যে সেকশনগুলো ক্লায়েন্ট
> নিজে বদলাতে চান (ব্যানার, অফার, ব্লগ) শুধু সেগুলো CMS-এ সরাবেন। সব সেকশন
> শুরুতেই CMS-এ বাঁধলে অকারণে ধীর হয়ে যাবে।

## ৩. কম্পোনেন্ট — ফোল্ডার প্রতি একটা

```
src/components/karmo/home/
├── Hero/
│   ├── Hero.jsx          ← মূল কম্পোনেন্ট
│   ├── HeroSlide.jsx     ← শুধু এটার নিজস্ব অংশ
│   └── index.js          ← export { default } from "./Hero"
├── DivisionPanels/
├── Collections/
└── shared/               ← একাধিক পেজে ব্যবহৃত
    ├── SectionHeading/
    └── VideoModal/
```

`index.js` থাকলে import ছোট থাকে (`@/components/karmo/home/Hero`), আর ভেতরে
ফাইল ভাঙলেও বাইরের কোনো import বদলাতে হয় না।

> **সৎ কথা:** `VideoModal`-এর মতো এক-ফাইলের কম্পোনেন্টে ফোল্ডার বাড়তি ঝামেলা।
> কিন্তু দুই মাস আর অনেক পেজের হিসাবে **একটা নিয়ম সবখানে** মানার মূল্য
> প্রতিটা কম্পোনেন্টে আলাদা সিদ্ধান্তের চেয়ে বেশি। তাই নিয়মটাই রাখছি।

## ৪. দ্রুততা

**প্রথমেই বলি — এখন কোড অপ্টিমাইজ করে লাভ নেই।** হোমপেজ ১০৭ MB অ্যাসেট পাঠায়।
তার পাশে code splitting বা lazy loading-এর সাশ্রয় শূন্যের সমান। ক্রম এই:

1. **ছবি রূপান্তর** — ১০৭ MB → আনুমানিক ৪-৫ MB। ৯৫%+ সাশ্রয়, বাকি সবকিছুর
   চেয়ে বড়
2. **ভিডিও রি-এনকোড** — ৩৪ MB। `reel-4` ছয় সেকেন্ডের জন্য ৬.২ MB (~৮ Mbps),
   ছোট নিঃশব্দ লুপের জন্য দশ ভাগের এক ভাগই যথেষ্ট
3. **`sizes` ঠিক রাখা** — `next/image` এই মানটা দেখে সিদ্ধান্ত নেয় কোন মাপের
   ফাইল পাঠাবে। ভুল থাকলে বড় ফাইল যায়। প্রোডাক্ট গ্রিডে একটা ভুল ছিল, ঠিক
   করেছি — নতুন কম্পোনেন্টে প্রতিবার মিলিয়ে নিতে হবে
4. **নিচের সেকশনগুলো দেরিতে লোড** — ফিল্ম স্ট্রিপ ইতিমধ্যেই তাই করে (পর্দায় না
   আসা পর্যন্ত কিছু নামায় না); বাকিগুলোতেও একই নিয়ম
5. **তারপর** কোডের হিসাব

## ৫. কীভাবে এগোব

**ধাপ ১ — ছবির নিয়ম চালু** (আগে, কারণ প্রতিদিন নতুন ছবি আসছে)
রূপান্তরের স্ক্রিপ্ট, ফোল্ডারের নিয়ম, আর এখনকার ১০৭ MB একবারে ঠিক করা।

**ধাপ ২ — একটা কম্পোনেন্টে পরীক্ষা**
শুধু `Hero` নতুন কাঠামোয় সরিয়ে দেখা — ফোল্ডার, `content/home.ts`। পছন্দ হলে
বাকি ১৫টা, নাহলে এক ধাপ পিছিয়ে আসা সহজ।

**ধাপ ৩ — বাকি কম্পোনেন্ট**, একটা একটা করে।

**ধাপ ৪ — পরের পেজ** এই কাঠামোতেই শুরু।

প্রতিটা পেজের ডিজাইন রেফারেন্স আগের মতোই `docs/pages/` এ যাবে।
